# SparkTC.scala 源码分析

## 类的概述和定义

`SparkTC` 是一个Spark示例程序，实现了图的传递闭包(Transitive Closure)算法。传递闭包是图论中的重要概念，用于计算图中所有可达的节点对，在路径查询、可达性分析等领域有广泛应用。

**程序定位**：这是一个图算法教学示例，主要用于学习如何在分布式环境中实现复杂的图论算法。程序展示了Spark在处理图数据方面的强大能力。

**核心功能**：
- 生成随机图数据用于测试
- 实现分布式传递闭包算法
- 使用迭代连接方法计算可达路径
- 支持大规模图的传递闭包计算

## 程序入口参数说明

程序接受一个可选命令行参数：
- `slices`：分区数量，控制并行任务数量，默认为2

- **oldCount**：上一轮迭代的边数

## 传递闭包算法原理分析

### 1. 传递闭包定义
**数学定义**：图G=(V,E)的传递闭包是图G*=(V,E*)，其中E*包含所有从u到v的可达路径对应的边。

**可达性关系**：如果存在路径u→v，则(u,v)∈E*

### 2. 迭代连接算法
**算法思想**：
- **基础路径**：初始传递闭包包含所有直接边
- **路径扩展**：每次迭代将路径长度增加1
- **连接操作**：通过连接发现新的可达关系
- **收敛条件**：当没有新路径被发现时算法终止

**数学公式**：
```
TC_{i+1} = TC_i ∪ {(x,z) | ∃y: (x,y)∈TC_i ∧ (y,z)∈E}
```

### 3. 收敛性分析
**收敛特性**：
- **有限性**：对于n个顶点的图，最多需要n-1次迭代
- **单调性**：每次迭代传递闭包不会缩小
- **固定点**：当传递闭包不再变化时达到固定点

## 分布式算法设计特点

### 1. 数据预处理阶段
```scala
val edges = tc.map(x => (x._2, x._1))
```
**反向边构建**：
- **键值转换**：将边(from, to)转换为(to, from)
- **连接准备**：为后续的连接操作准备键值对
- **优化设计**：通过键值对格式优化连接性能

### 2. 迭代计算阶段
```scala
do {
  oldCount = nextCount
  tc = tc.union(tc.join(edges).map(x => (x._2._2, x._2._1))).distinct().cache()
  nextCount = tc.count()
} while (nextCount != oldCount)
```
**迭代流程**：
1. **计数保存**：保存当前传递闭包的边数
2. **连接扩展**：通过连接操作发现新路径
3. **结果合并**：将新路径与原有路径合并
4. **去重处理**：去除重复的边关系
5. **缓存优化**：缓存结果提高性能
6. **收敛判断**：比较边数变化判断是否收敛

### 3. 连接操作详解
```scala
tc.join(edges).map(x => (x._2._2, x._2._1))
```
**连接逻辑**：
- **tc数据**：包含已知路径(from, to)
- **edges数据**：包含反向边(to, from)
- **连接结果**：生成(y, ((from, to), from))格式
- **路径构造**：通过映射构造新路径(from, from)

## 与相关算法的对比分析

### 1. 与Warshall算法对比
**Warshall算法（单机）**：
- **计算模式**：使用邻接矩阵进行三重循环
- **空间复杂度**：O(n²)的矩阵存储
- **时间复杂度**：O(n³)的三重循环

**SparkTC算法（分布式）**：
- **计算模式**：使用迭代连接进行路径扩展
- **空间复杂度**：只存储实际存在的边
- **时间复杂度**：与图直径相关，通常O(diameter)

### 2. 与DFS/BFS算法对比
**DFS/BFS算法**：
- **计算模式**：从每个顶点出发进行遍历
- **并行性**：不同顶点的遍历可以并行
- **适用性**：适合单源或多源可达性查询

**SparkTC算法**：
- **计算模式**：全局迭代计算所有可达关系
- **并行性**：基于数据并行的分布式计算
- **适用性**：适合计算完整的传递闭包
