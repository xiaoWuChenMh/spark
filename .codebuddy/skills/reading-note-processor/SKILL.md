# 读书笔记处理器

## 概述

本技能按照分步确认的工作流程，先收集书籍基本信息并确认，然后收集零散阅读素材并确认，接着还原作者写书的逻辑框架，判断读物类型，询问笔记使用目的，最后将零散阅读素材转化为标准化知识点，选择合适的逻辑骨架将知识点封装起来。在选择逻辑骨架时，将原作者的逻辑框架作为重要参考变量，通过四级判断标准（读物类型匹配、内容复杂度、使用场景、原作者框架参考）综合评估，实现从"作者语境"到"自我语境"的重编码，确保所有知识点具备"高内聚、低耦合"特征，便于后续双链调用。

## 工作流程

### 第一步：输入书籍基本信息
**重要：此步骤仅收集书籍元数据，不包含具体阅读内容**

1. 明确告知用户："现在请提供书籍的基本信息（可选），包括：书名、作者、目录结构、前言/简介等"
2. 用户输入书籍基本信息后，AI必须：
   - 确认收到的是书籍基本信息而非阅读素材
   - 询问："请确认这些是书籍的基本信息（书名、作者、目录等），确认无误后我们将进入阅读素材收集阶段"
3. 用户确认书籍基本信息无误后，AI必须明确标识："书籍基本信息确认完成，现在进入第二步：阅读素材收集"

### 第二步：输入零散阅读素材
**重要：此步骤收集具体的阅读内容，与第一步的书籍基本信息完全区分**

1. 明确告知用户："现在请提供您想要整理的零散阅读素材，包括：重点划线、灵感笔记、人工整理的笔记、任何您觉得有价值的内容片段等"
2. 用户输入阅读素材后，AI必须：
   - 确认收到的是阅读素材而非书籍基本信息
   - 询问："请确认这些是您的阅读素材（重点划线、笔记等），确认无误后我们将进入逻辑框架分析阶段"
3. 用户确认阅读素材无误后进入下一步；

### 第三：读物类型判断
根据`读物类型指南.md`中的详细算法进行判断，输出标准格式：

```json
{
  "core_type": "核心类型（实用型/理论型/想象文学）",
  "secondary_types": ["二级分类数组"],
  "structure_type": "结构类型（强结构/弱结构）",
  "hybrid_flag": "是否为混合类型（true/false）",
  "confidence": "置信度（0-1之间的浮点数）"
}
```

#### 3.1 核心类型识别算法
**阶段1：核心类型判断**
```
步骤1：检查是否为想象文学
    如果标题包含想象文学触发词 AND (前言包含想象文学特征 OR 章节抽样为叙事性内容)
    则标记为"想象文学"

步骤2：检查是否为实用型
    如果(标题包含实用型触发词 > 理论型触发词) OR (前言实用特征词频 > 理论特征词频)
    则标记为"实用型"

步骤3：默认为理论型
```

#### 3.2 细化分类算法
**阶段2：二级分类识别**
- **想象文学**：小说、诗歌、戏剧
- **理论型**：历史类、科学类、哲学类、数学类、社会科学类、心理学类、脑科学类、医学理论类、理论综合类
- **实用型**：商业管理类、技能训练类、工具参考类、健康生活类、教育培训类、个人发展类、技术应用类、临床医学类、亲密关系类、实用综合类

#### 3.3 混合类型处理
**阶段3：混合类型判断**
```
混合类型识别条件：
1. 多领域混合：理论型或实用型中检测到多个领域且频率相近
2. 理论-实用混合：实用型得分 > 0.3 AND 理论型得分 > 0.3 AND 得分差 < 0.2
```

#### 3.4 置信度计算
```
基础置信度 = 0.7
加分项：
- 标题特征明显 +0.1
- 前言特征明显 +0.15
- 目录结构清晰 +0.05
- 抽样内容支持判断 +0.1

减分项：
- 信息不足（只有标题） -0.2
- 类型特征冲突 -0.15
- 领域特征模糊 -0.1

最终置信度限制在0.5-0.95之间
```

#### 3.5 结构分析
```
结构强度 = (章节间关联度 + 逻辑顺序明显度) / 2
IF 结构强度 > 0.6 THEN 标记为"强结构"
ELSE 标记为"弱结构"
```

### 第四步：询问笔记使用目的
1. 询问用户希望笔记主要用于什么目的？（深度学习、快速应用、分析研究等）；

### 第五步：逻辑框架还原
1. 根据用户输入的素材还原作者写书的逻辑框架；
2. 绘制思维导图展示框架结构；
3. 用户确认框架还原是否正确；
4. 如有需要，配合用户迭代修改；

### 第六步：读书笔记生成
首先，根据输入的素材和原作者写书的逻辑框架，拆解并构建知识点；
然后，选择最适配的**逻辑骨架（Skeleton）**将知识点封装起来，不一定沿用原作者写书的逻辑框架；

#### 6.1 内容"脱水"与"去垢"
- 删除冗余：删掉所有为了凑字数而存在的学术背景、啰唆词汇和不必要的案例
- 提取主干：识别作者使用的组织关系（如递进、转折），只保留对我有价值的模块

#### 6.2 重编码与转义（用自己的话记笔记）
- 禁止复制：严禁直接复制原文，将"作者语境"翻译为"我的语言系统"
- 融入灵感：将用户的"灵感笔记"与知识点深度融合，记录"反直觉"或"有启发"的信息

#### 6.3 选择最适配的**逻辑骨架（Skeleton）**
根据以下判断标准选择最合适的逻辑骨架（参考`逻辑骨架框架库.md`）：

**一级判断：读物类型匹配**
- 理论性读物 → 树状分类、因果解释、道-法-术-器
- 实用性读物 → 流程序列、问题-解决方案、2W1H
- 分析性读物 → 论点案例、5W1H、比较分析
- 叙事性读物 → 时间线、因果解释
- 描述性读物 → 空间结构、树状分类

**二级判断：内容复杂度**
- 高复杂度 → 5W1H、道-法-术-器、增强调节回路
- 中复杂度 → 因果解释、论点案例、比较分析
- 低复杂度 → 2W1H、流程序列、问题-解决方案

**三级判断：使用场景**
- 深度学习 → 选择全面系统的框架（5W1H、道-法-术-器）
- 快速应用 → 选择简洁高效的框架（2W1H、流程序列）
- 分析研究 → 选择分析性强的框架（因果解释、论点案例）
- 记忆理解 → 选择结构清晰的框架（树状分类、时间线）

**四级判断：原作者框架参考**
将第三步还原的作者逻辑框架作为重要参考变量：
- **框架适配度评估**：评估各候选骨架与原框架的兼容性（0-1分）
- **继承价值判断**：分析原框架中值得保留的组织逻辑
- **创新空间识别**：识别原框架的局限性和改进机会
- **权重分配**：原作者框架参考权重占总体决策的20-30%

**参考框架应用规则**：
1. 如果原框架结构清晰且适合当前目的，可适度沿用其组织逻辑
2. 如果原框架存在明显缺陷，优先选择更优的替代骨架
3. 对于混合型内容，可融合原框架优势与新骨架特点
4. 始终以用户的使用目的和知识吸收效率为最终导向

**冲突解决原则**
1. 主导性原则：选择与读物主要特征最匹配的框架
2. 实用性原则：优先考虑实际应用需求
3. 完整性原则：确保框架能够覆盖主要内容
4. 效率原则：在效果相当的情况下选择更简洁的框架
5. **传承性原则**：在满足前四条原则基础上，适当考虑原框架的合理继承

#### 6.4 构建知识点
每个知识点包含（参考`知识点模板.md`）：
- **所属主题**：该知识点可以为哪些主题提供理论支撑
- **主旨**（是什么）：用一句话精炼阐述该知识点的判断或结论
- **论述**（为什么）：记录逻辑推导过程。向上追问"所以呢（结论）"，向下追问"为什么（证据）"
- **适用边界**：明确该知识在什么场景下有效，在什么条件下会失效
- **我的反思**：挂载用户原始素材中的灵感、反直觉点或切肤之痛

#### 6.5 构建知识图谱
将所有知识点按照选择的"逻辑骨架"组织在一起。使用`思维导图模板.md`中的相应模板。

#### 6.6 输出辅助模块
在构建知识点和知识图谱后，根据内容特性输出相应的辅助模块。辅助模块作为知识点的补充和增强，提供更具体、实用的信息单元。

**概念模块**
- **触发条件**：当笔记内容中包含需要详细说明的核心概念、术语定义、专业名词时
- **模块内容**：
  1. 概念名称：明确标识需要解释的概念
  2. 定义说明：用简洁清晰的语言给出准确的定义
  3. 特征描述：列举概念的关键特征或属性
  4. 关联知识：说明该概念与其他知识点的联系
  5. 示例说明：提供具体的应用示例帮助理解

**工具模块**
- **触发条件**：当笔记内容中包含具体工具、方法、技术、操作流程的使用说明时
- **模块内容**：
  1. 工具名称：明确标识工具或方法
  2. 功能说明：说明工具的主要功能和作用
  3. 使用步骤：提供清晰的使用流程或操作步骤
  4. 适用场景：指出在什么情况下使用该工具最有效
  5. 注意事项：列出使用时的关键注意事项和常见错误
  6. 实践示例：提供具体的应用示例或案例

**思维模型模块**
- **触发条件**：当笔记内容中包含思维框架、认知模型、决策模型、分析框架的介绍和使用说明时
- **模块内容**：
  1. 模型名称：明确标识思维模型或框架
  2. 核心原理：阐述模型的基本原理和逻辑结构
  3. 应用领域：说明该模型适用的领域和场景
  4. 使用步骤：提供具体的应用流程和方法
  5. 案例演示：通过具体案例展示模型的实际应用
  6. 变体扩展：如有，说明模型的变体或扩展应用

**模块输出规则**
1. 自动检测：系统自动分析知识点内容，识别是否包含概念、工具或思维模型的说明
2. 按需输出：只有检测到相关内容的才会输出相应模块，避免不必要的输出
3. 模块分离：三个模块相互独立，每个模块都有明确的结构和格式
4. 位置安排：辅助模块放置在知识点之后、知识图谱之前，作为补充信息
5. 标记标识：每个模块都有明确的标题标记，如"【概念模块】"、"【工具模块】"、"【思维模型模块】"

**输出示例**
```
【概念模块】
概念名称：认知失调
定义说明：当个体持有两种或更多相互矛盾的信念、价值观或想法时产生的心理不适
特征描述：心理紧张、寻求一致性、态度改变倾向
关联知识：与态度改变、决策理论、自我合理化相关
示例说明：抽烟者知道吸烟有害健康但仍继续吸烟，产生认知失调

【工具模块】
工具名称：SWOT分析
功能说明：评估项目或组织的优势、劣势、机会和威胁
使用步骤：1) 列出内部优势劣势 2) 识别外部机会威胁 3) 交叉分析制定策略
适用场景：战略规划、项目评估、市场竞争分析
注意事项：避免主观偏见，确保数据客观，定期更新分析
实践示例：新产品上市前的SWOT分析

【思维模型模块】
模型名称：第一性原理
核心原理：将问题分解到最基本的元素，然后从这些基本元素出发重新构建解决方案
应用领域：产品创新、问题解决、战略思考
使用步骤：1) 识别当前假设 2) 分解到基本事实 3) 重建解决方案
案例演示：埃隆·马斯克用第一性原理重新思考电池成本
变体扩展：逆向思维、零基础思考
```

## 快速使用指南

### 单次处理流程
1. 用户提供书籍基本信息（可选）→ AI确认收到的是书籍基本信息而非阅读素材 → 用户确认无误
2. 用户提供零散阅读素材 → AI确认收到的是阅读素材而非书籍基本信息 → 用户确认无误
3. 系统还原作者写书的逻辑框架
4. 自动判断读物类型（使用标准算法）
5. 询问用户笔记使用目的
6. 根据判断标准选择逻辑骨架
7. 生成标准化知识点
8. 构建知识图谱

### 批量处理建议
- 同类读物可以复用相同的逻辑骨架
- 建立个人化的骨架偏好库
- 定期回顾和优化骨架选择标准
