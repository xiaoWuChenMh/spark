# ExecutionMemoryPool 源码分析

## 类的概述和定义

`ExecutionMemoryPool` 是 Spark 内存管理系统的核心组件之一，负责实现任务间共享可调整大小内存池的策略和簿记机制。该类继承自 `MemoryPool` 并实现了 `Logging` 接口。

**主要职责：**
- 管理执行内存池的分配和释放
- 确保任务间的公平内存分配
- 实现内存分配时的阻塞和唤醒机制
- 跟踪每个任务的内存使用情况

**类定义：**
```scala
private[memory] class ExecutionMemoryPool(
    lock: Object,
    memoryMode: MemoryMode
) extends MemoryPool(lock) with Logging
```

## 构造函数参数说明

| 参数名 | 类型 | 说明 |
|--------|------|------|
| `lock` | `Object` | 用于同步的锁对象，通常是 `MemoryManager` 实例 |
| `memoryMode` | `MemoryMode` | 内存模式，标识跟踪的是堆内内存还是堆外内存 |

## 核心属性分析

### 1. poolName
- **类型**: `String`
- **作用**: 根据内存模式生成池名称（"on-heap execution" 或 "off-heap execution"）
- **访问权限**: `private[this]`

### 2. memoryForTask
- **类型**: `mutable.HashMap[Long, Long]`
- **作用**: 存储任务ID到内存消耗的映射关系
- **同步机制**: 使用 `@GuardedBy("lock")` 注解确保线程安全
- **键**: 任务尝试ID (`taskAttemptId`)
- **值**: 内存使用字节数

### 3. memoryUsed（重写方法）
- **作用**: 返回池中所有任务使用的总内存量
- **实现**: 对 `memoryForTask.values.sum` 进行同步访问

## 主要方法分类和说明

### 内存查询方法

#### getMemoryUsageForTask
- **功能**: 获取指定任务的内存使用量
- **参数**: `taskAttemptId: Long` - 任务尝试ID
- **返回值**: 任务当前使用的内存字节数
- **同步**: 使用 `lock.synchronized` 确保线程安全

### 内存分配方法

#### acquireMemory
**核心方法，实现复杂的内存分配逻辑：**

**参数说明：**
- `numBytes: Long` - 请求的内存字节数
- `taskAttemptId: Long` - 任务尝试ID
- `maybeGrowPool: Long => Unit` - 可选的池扩展回调函数
- `computeMaxPoolSize: () => Long` - 计算最大池大小的回调函数

**分配策略：**
1. **公平分配原则**: 每个任务最多可获得 `1/N` 的内存，最少保证 `1/(2N)`
2. **动态调整**: 根据活跃任务数量动态计算分配限额
3. **阻塞等待**: 当内存不足时，任务会等待其他任务释放内存

**算法流程：**
1. 将任务添加到内存跟踪映射中
2. 循环检查内存分配条件
3. 计算每个任务的最大和最小内存限额
4. 根据空闲内存和限额决定分配量
5. 必要时阻塞等待内存释放

### 内存释放方法

#### releaseMemory
- **功能**: 释放指定任务的部分内存
- **参数**: `numBytes: Long` - 要释放的字节数，`taskAttemptId: Long` - 任务ID
- **安全机制**: 检查释放量不超过当前使用量
- **通知机制**: 释放后通知等待的任务

#### releaseAllMemoryForTask
- **功能**: 释放指定任务的所有内存并标记为不活跃
- **返回值**: 实际释放的内存字节数
- **使用场景**: 任务结束时调用

## 设计特点总结

### 1. 公平性设计
- **动态配额**: 根据活跃任务数量动态调整每个任务的内存配额
- **最小保证**: 确保每个任务至少获得 `1/(2N)` 的内存份额
- **防止饥饿**: 避免某个任务占用过多内存导致其他任务频繁溢出

### 2. 同步机制
- **锁对象复用**: 使用外部的 `lock` 对象进行同步
- `@GuardedBy` 注解: 明确标识需要同步保护的字段
- `wait()/notifyAll()`: 实现内存不足时的阻塞和唤醒

### 3. 扩展性设计
- **回调函数**: 通过 `maybeGrowPool` 和 `computeMaxPoolSize` 支持池的动态扩展
- **内存模式支持**: 支持堆内和堆外两种内存模式

### 4. 错误处理
- **参数验证**: 检查请求的内存字节数必须大于0
- **安全释放**: 释放内存时检查不会释放超过当前使用量的内存
- **日志记录**: 记录重要的内存操作事件

## 配置参数说明

该类本身不直接暴露配置参数，但通过以下方式与配置系统交互：

### 间接配置参数
- **池大小**: 通过父类 `MemoryPool` 的 `poolSize` 属性配置
- **内存模式**: 通过构造函数参数指定，反映 Spark 的内存配置

### 动态计算参数
- **最大池大小**: 通过 `computeMaxPoolSize` 回调函数动态计算
- **活跃任务数**: 运行时根据 `memoryForTask.keys.size` 动态确定

## 补充分析

### 内存管理策略演进
- **Spark 1.6 之前**: 由 `ShuffleMemoryManager` 负责任务间内存仲裁
- **当前版本**: 使用 `ExecutionMemoryPool` 实现更精细的内存管理

### 性能优化考虑
- **减少锁竞争**: 使用细粒度的同步块
- **避免死锁**: 清晰的锁获取和释放顺序
- **内存效率**: 使用基本类型减少对象开销

### 使用场景
- **Shuffle 操作**: 管理 Shuffle 读写所需的内存
- **聚合操作**: 控制聚合过程中的内存使用
- **排序操作**: 管理排序算法的内存需求

### 线程安全保证
- **所有公共方法**都使用 `lock.synchronized` 确保线程安全
- **内部状态**通过同步机制保护一致性
- **通知机制**确保等待任务能及时获得内存

该类是 Spark 内存管理系统的关键组件，通过精心的设计确保了任务间内存分配的公平性和系统的稳定性。
