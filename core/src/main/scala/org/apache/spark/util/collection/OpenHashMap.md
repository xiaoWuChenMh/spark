# OpenHashMap 源码分析

## 类的概述和定义

`OpenHashMap` 是一个快速的哈希映射实现，专门为可空键设计。该类继承自 `Iterable[(K, V)]` 并实现了 `Serializable` 接口，提供了比 `java.util.HashMap` 快5倍的性能，同时使用更少的内存开销。

**核心设计理念**：基于开放地址法的哈希映射，支持插入和更新操作，但不支持删除操作，特别优化了空键的处理。

## 构造函数参数说明

```scala
class OpenHashMap[K : ClassTag, @specialized(Long, Int, Double) V: ClassTag](
    initialCapacity: Int)
```

### 类型参数说明
- **`K : ClassTag`**：键的类型，需要 `ClassTag` 上下文绑定以支持数组创建
- **`@specialized(Long, Int, Double) V: ClassTag`**：值的类型，对常用数值类型进行特殊化优化

### 构造函数重载
- **主构造函数**：`(initialCapacity: Int)` - 指定初始容量
- **默认构造函数**：`this() = this(64)` - 使用默认容量64

## 核心属性分析

### 数据存储属性
- **`_keySet: OpenHashSet[K]`**：存储键的开放哈希集合
- **`_values: Array[V]`**：存储值的数组，与键集合位置对应
- **`_oldValues: Array[V]`**：扩容时临时存储旧值的数组

### 空键处理属性
- **`haveNullValue: Boolean`**：标记是否包含空键
- **`nullValue: V`**：空键对应的值

### 特殊化优化
- **`@specialized`注解**：对 `Long`、`Int`、`Double` 类型进行特殊化处理
- **避免装箱开销**：通过特殊化减少基本类型的装箱操作

## 主要方法分类和说明

### 数据访问方法

#### `contains(k: K): Boolean` - 检查键是否存在
- **功能**：检查映射中是否包含指定的键
- **空键处理**：对空键进行特殊检查
- **实现逻辑**：
  - 空键：检查 `haveNullValue` 标志
  - 非空键：通过 `_keySet.getPos` 检查位置有效性

#### `apply(k: K): V` - 获取值
- **功能**：根据键获取对应的值
- **返回值**：如果键不存在返回 `null.asInstanceOf[V]`
- **实现细节**：
  - 空键：直接返回 `nullValue`
  - 非空键：通过位置查找值数组

### 数据修改方法

#### `update(k: K, v: V): Unit` - 设置值
- **功能**：设置键值对，如果键已存在则更新值
- **核心逻辑**：
  - **空键处理**：设置 `haveNullValue` 和 `nullValue`
  - **非空键处理**：
    1. 调用 `addWithoutResize` 添加键并获取位置
    2. 使用位掩码提取有效位置
    3. 在值数组中设置值
    4. 检查是否需要重新哈希

#### `changeValue(k: K, defaultValue: => V, mergeValue: (V) => V): V` - 原子更新值
- **功能**：原子性地更新键对应的值
- **参数说明**：
  - `defaultValue: => V`：键不存在时的默认值（惰性求值）
  - `mergeValue: (V) => V`：键存在时的合并函数
- **应用场景**：适合需要读取-修改-写入原子操作的场景

### 迭代器方法

#### `iterator: Iterator[(K, V)]` - 迭代器
- **功能**：返回映射中所有键值对的迭代器
- **实现特点**：
  - **空键优先**：首先处理空键（如果存在）
  - **顺序遍历**：使用 `_keySet.nextPos` 按顺序遍历
  - **惰性计算**：按需计算下一个键值对

### 内部辅助方法

#### `grow(newCapacity: Int): Unit` - 扩容方法
- **功能**：将值数组扩容到新容量
- **实现**：
  - 保存旧值数组到 `_oldValues`
  - 创建新容量的值数组

#### `move(oldPos: Int, newPos: Int): Unit` - 数据迁移
- **功能**：在扩容时将数据从旧位置移动到新位置
- **调用时机**：由 `OpenHashSet.rehashIfNeeded` 调用

## 设计特点总结

### 性能优化设计

#### 开放地址法哈希
- **冲突解决**：使用开放地址法解决哈希冲突
- **线性探测**：通过 `OpenHashSet` 的线性探测算法
- **内存局部性**：键值对紧凑存储提高缓存命中率

#### 特殊化优化
- **值类型优化**：对常用数值类型进行特殊化处理
- **避免装箱**：减少基本类型的装箱拆箱开销
- **数组存储**：直接使用原生数组提高访问效率

### 内存效率设计

#### 紧凑存储结构
- **分离存储**：键和值分别存储在优化后的结构中
- **内存对齐**：利用数组的连续内存特性
- **容量控制**：动态调整容量避免内存浪费

#### 空键优化
- **特殊处理**：将空键单独存储，避免在数组中占用位置
- **标志位管理**：使用布尔标志记录空键存在状态
- **性能提升**：避免对空键的哈希计算和冲突处理

### 扩容机制设计

#### 增量扩容
- **按需扩容**：只在需要时进行扩容
- **渐进迁移**：使用临时数组平滑迁移数据
- **重新哈希**：在扩容时重新计算哈希分布

#### 位掩码操作
- **位置提取**：使用 `POSITION_MASK` 提取有效位置
- **状态判断**：使用 `NONEXISTENCE_MASK` 判断键是否存在
- **高效计算**：位运算替代算术运算提高性能
