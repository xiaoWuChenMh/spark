# AppendOnlyMap 源码分析

## 类的概述和定义

`AppendOnlyMap` 是一个专门为只追加（append-only）使用场景优化的简单开放哈希表实现。该类继承自 `Iterable[(K, V)]` 并实现了 `Serializable` 接口，属于 Spark 的开发者 API（`@DeveloperApi`）。

**核心设计理念**：键永远不会被移除，但每个键对应的值可以被更改。这种设计模式特别适合 Spark 中需要频繁更新但不需要删除的场景。

## 构造函数参数说明

```scala
class AppendOnlyMap[K, V](initialCapacity: Int = 64)
```

- **initialCapacity**: 初始容量，默认为64。必须是正整数且不能超过最大容量限制（`MAXIMUM_CAPACITY = 1 << 29`）
- **类型参数**：
  - `K`: 键的类型
  - `V`: 值的类型

## 核心属性分析

### 容量相关属性
- `LOAD_FACTOR = 0.7`: 负载因子，当元素数量达到容量的70%时触发扩容
- `capacity`: 当前容量，始终为2的幂次方
- `mask = capacity - 1`: 用于快速计算哈希位置的掩码
- `curSize`: 当前元素数量
- `growThreshold`: 扩容阈值，计算公式为 `LOAD_FACTOR * capacity`

### 数据存储属性
- `data`: 存储键值对的数组，采用交错存储方式（key0, value0, key1, value1, ...）以提高内存局部性
- `haveNullValue`: 标记是否包含空键
- `nullValue`: 空键对应的值

### 状态控制属性
- `destroyed`: 标记映射是否已被破坏性排序操作破坏
- `destructionMessage`: 映射被破坏时的错误消息

## 主要方法分类和说明

### 数据访问方法

#### `apply(key: K): V` - 获取值
- **功能**：根据键获取对应的值
- **实现细节**：
  - 使用二次探测法解决哈希冲突
  - 对空键进行特殊处理
  - 通过 `rehash` 方法优化哈希分布

#### `update(key: K, value: V): Unit` - 设置值
- **功能**：设置键值对，如果键已存在则更新值
- **实现细节**：
  - 插入新键时会调用 `incrementSize()` 检查是否需要扩容
  - 使用相同的二次探测算法定位插入位置

#### `changeValue(key: K, updateFunc: (Boolean, V) => V): V` - 原子更新值
- **功能**：原子性地更新键对应的值
- **参数说明**：
  - `updateFunc`: 更新函数，接收两个参数：是否已存在该键、旧值（不存在时为null）
- **应用场景**：适合需要读取-修改-写入原子操作的场景

### 迭代器方法

#### `iterator: Iterator[(K, V)]` - 普通迭代器
- **功能**：返回映射中所有键值对的迭代器
- **实现特点**：支持空键的特殊处理，按数组顺序遍历

#### `destructiveSortedIterator(keyComparator: Comparator[K]): Iterator[(K, V)]` - 破坏性排序迭代器
- **功能**：返回排序后的迭代器，但会破坏映射的后续使用
- **实现机制**：
  - 先将有效键值对压缩到数组前端
  - 使用 `Sorter` 进行排序
  - 设置 `destroyed = true` 标记映射已破坏

### 内部辅助方法

#### `incrementSize(): Unit` - 增加大小并检查扩容
- **功能**：增加元素计数，检查是否达到扩容阈值
- **触发条件**：当 `curSize > growThreshold` 时调用 `growTable()`

#### `growTable(): Unit` - 扩容表
- **功能**：将哈希表容量翻倍并重新哈希所有元素
- **实现细节**：
  - 创建新容量的数组
  - 使用相同的哈希算法重新插入所有元素
  - 更新相关属性（capacity, mask, growThreshold）

#### `rehash(h: Int): Int` - 重新哈希
- **功能**：使用 MurmurHash3 对原始哈希值进行重新哈希
- **目的**：解决哈希函数在低位变化不足的问题

#### `nextPowerOf2(n: Int): Int` - 计算下一个2的幂
- **功能**：返回不小于n的最小2的幂次方数

## 设计特点总结

### 哈希冲突解决策略
- **二次探测法**：使用公式 `pos = (pos + i) & mask` 进行探测，其中i从1开始递增
- **保证完全探测**：由于容量是2的幂次方，二次探测法能够探测所有槽位

### 内存优化设计
- **交错存储**：键值对交替存储在同一个数组中，提高缓存局部性
- **空键优化**：单独处理空键，避免在数组中存储null键
- **容量控制**：使用2的幂次方容量，便于使用位运算进行快速计算

### 性能优化点
- **负载因子控制**：0.7的负载因子在空间利用率和性能之间取得平衡
- **动态扩容**：按需扩容，避免一次性分配过大内存
- **哈希优化**：使用MurmurHash3改善哈希分布

## 配置参数说明

### 硬编码参数
- `LOAD_FACTOR = 0.7`: 控制哈希表的填充程度
- `MAXIMUM_CAPACITY = 1 << 29`: 最大容量限制（约5.37亿）

### 可配置参数
- `initialCapacity`: 初始容量，影响初始内存分配和性能

## 异常处理机制

### 前置条件检查
- 构造函数中对初始容量进行有效性验证
- 操作前检查映射是否已被破坏性排序破坏

### 运行时异常
- `NoSuchElementException`: 迭代器越界时抛出
- `IllegalArgumentException`: 容量超出限制时抛出

## 使用场景和最佳实践

### 适用场景
1. **聚合操作**：Spark中的reduceByKey等操作
2. **累加器模式**：需要频繁更新值的场景
3. **只追加数据结构**：键不需要删除的应用

### 最佳实践
1. **合理设置初始容量**：根据预估数据量设置，避免频繁扩容
2. **避免混用迭代器**：破坏性排序迭代器使用后不能再使用普通操作
3. **注意空键处理**：空键有特殊处理逻辑，需要特别注意

## 性能优化点分析

### 内存效率
- 紧凑的数组存储减少内存开销
- 交错存储提高缓存命中率
- 避免对象装箱开销

### 计算效率
- 位运算替代模运算提高性能
- 二次探测法减少冲突概率
- MurmurHash3提供良好的哈希分布

## 与其他模块的交互关系

- **依赖**：使用Google Guava的Hashing库进行重新哈希
- **被依赖**：被Spark的shuffle、聚合等模块使用
- **协作**：与`Sorter`类配合实现破坏性排序功能
