# PercentileHeap 类分析文档

## 类的概述和定义

`PercentileHeap` 是 Spark 中用于快速跟踪一组可能包含重复值的数字的百分位数的数据结构。它采用双堆设计，能够在 O(log n) 时间复杂度内插入新数字，在 O(1) 时间复杂度内确定百分位数。

该类位于 `org.apache.spark.util.collection` 包中，是一个私有类，主要用于 Spark 内部的数据处理场景。

**核心设计思想**：维护两个堆 - `smallerHalf` 和 `largerHalf`，分别存储较小的一半数字和较大的一半数字。通过动态调整两个堆的大小比例，使其符合指定的百分位比例要求。

## 构造函数参数说明

```scala
class PercentileHeap(percentage: Double = 0.5)(implicit val ord: Ordering[Double])
```

### 参数详解：

- **percentage: Double = 0.5**
  - 要计算的百分位数比例，默认值为 0.5（即中位数）
  - 取值范围：[0, 1]，通过断言确保合法性
  - 例如：0.9 表示计算第 90 百分位数

- **ord: Ordering[Double]**
  - 隐式参数，用于定义 Double 类型的排序规则
  - 确保堆中元素的正确排序

## 核心属性分析

### 1. smallerHalf 堆
```scala
private[this] val smallerHalf = PriorityQueue.empty[Double](ord)
```
- **作用**：存储所有小于当前百分位数的数字
- **特点**：最大堆结构，堆顶元素是当前较小一半中的最大值
- **排序规则**：使用传入的 Ordering[Double] 进行排序

### 2. largerHalf 堆
```scala
private[this] val largerHalf = PriorityQueue.empty[Double](ord.reverse)
```
- **作用**：存储所有大于当前百分位数的数字
- **特点**：最小堆结构，堆顶元素是当前较大一半中的最小值
- **排序规则**：使用反向排序，确保堆顶是最小值

## 主要方法分类和说明

### 状态检查方法

#### `isEmpty(): Boolean`
- **功能**：检查堆是否为空
- **实现**：同时检查两个堆是否都为空
- **时间复杂度**：O(1)

#### `size(): Int`
- **功能**：返回堆中元素总数
- **实现**：两个堆的大小之和
- **时间复杂度**：O(1)

#### `smallerSize(): Int`
- **功能**：返回较小堆的大小（主要用于测试）
- **实现**：直接返回 smallerHalf 的大小

### 数据操作方法

#### `insert(x: Double): Unit`
- **功能**：插入一个新数字到堆中
- **算法逻辑**：
  1. 如果堆为空，根据百分位数比例决定插入哪个堆
  2. 如果堆不为空，比较新数字与当前百分位数
  3. 大于百分位数插入 largerHalf，否则插入 smallerHalf
  4. 调用 rebalance() 重新平衡堆
- **时间复杂度**：O(log n)

#### `percentile: Double`
- **功能**：获取当前百分位数值
- **算法逻辑**：
  1. 检查堆是否为空，为空则抛出异常
  2. 计算当前大小比例的偏差
  3. 如果偏差很小（<1%），取两个堆顶的平均值
  4. 否则返回偏差较小一侧的堆顶元素
- **时间复杂度**：O(1)

### 内部平衡方法

#### `calculateDeviation(smallerSize: Int, largerSize: Int): Double`
- **功能**：计算当前堆大小与期望比例的偏差
- **计算公式**：`smallerSize * (1 - percentage) - largerSize * percentage`
- **返回值含义**：负值表示较小堆元素不足，正值表示较小堆元素过多

#### `rebalance(): Unit`
- **功能**：重新平衡两个堆的大小比例
- **平衡策略**：
  1. 计算当前偏差
  2. 如果偏差为正（较小堆元素过多），尝试移动一个元素到较大堆
  3. 如果偏差为负（较大堆元素过多），尝试移动一个元素到较小堆
  4. 只有当移动后偏差绝对值减小时才执行移动操作

## 设计特点总结

### 1. 双堆设计模式
- 采用 smallerHalf 和 largerHalf 两个堆分别管理数据
- 通过堆的性质快速维护数据的有序性
- 避免了对整个数据集进行排序的开销

### 2. 动态平衡机制
- 每次插入后自动调用 rebalance() 方法
- 确保两个堆的大小比例始终接近 percentage : (1 - percentage)
- 通过偏差计算实现智能的元素移动决策

### 3. 高效的时间复杂度
- **插入操作**：O(log n) - 堆插入的典型时间复杂度
- **查询操作**：O(1) - 直接访问堆顶元素
- 相比传统排序方法具有明显的性能优势

### 4. 鲁棒性设计
- 对空堆情况进行异常处理
- 通过断言确保参数合法性
- 支持重复值的正确处理

## 配置参数说明

### percentage 参数的影响
- **默认值 0.5**：计算中位数
- **接近 0**：计算较小的百分位数，smallerHalf 堆相对较小
- **接近 1**：计算较大的百分位数，largerHalf 堆相对较小

### 排序规则配置
- 通过隐式参数支持自定义排序规则
- 默认使用 Double 的自然排序
- 可根据需要提供特定的排序逻辑

## 性能优化点分析

### 1. 避免完全排序
- 传统百分位数计算需要对整个数据集排序，时间复杂度 O(n log n)
- PercentileHeap 通过堆结构避免了完全排序，插入时仅需 O(log n)

### 2. 智能平衡策略
- rebalance() 方法只在必要时移动元素
- 通过偏差计算确保移动操作的有效性
- 减少不必要的堆操作开销

### 3. 内存效率
- 双堆结构相比完整排序占用更少内存
- 支持流式数据处理，无需存储完整数据集

## 异常处理机制

### 空堆异常
- 当调用 percentile 方法但堆为空时，抛出 NoSuchElementException
- 提供清晰的错误信息便于调试

### 参数验证
- 构造函数中对 percentage 参数进行范围验证
- 使用断言确保参数合法性

## 使用场景和最佳实践

### 适用场景
1. **流式数据处理**：支持逐个插入数据并实时计算百分位数
2. **大数据集处理**：避免对完整数据集进行排序
3. **实时监控**：需要快速获取当前数据分布的百分位数

### 最佳实践
1. **参数选择**：根据实际需求设置合适的 percentage 值
2. **数据规模**：适用于中等规模的数据集，避免堆操作过多影响性能
3. **异常处理**：在使用 percentile 方法前检查堆是否为空

## 与其他模块的交互关系

- 作为 Spark util.collection 包的一部分
