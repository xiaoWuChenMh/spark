# Schedulable 接口分析

## 接口的概述和定义

`Schedulable` 是 Spark 调度器模块中的核心接口（trait），定义了可调度实体的通用契约。该接口为 Spark 的层次化调度系统提供了统一的抽象基础，支持 `Pool` 和 `TaskSetManager` 两种类型的可调度实体，实现了调度系统的模块化和可扩展性。

**接口定义：**
```scala
private[spark] trait Schedulable
```

**主要特性：**
- 私有访问权限，仅在 spark 包内可见
- 作为 trait（特质）定义，支持多继承
- 提供可调度实体的标准化接口
- 支持层次化调度结构的基础设施

**实体类型支持：**
- **Pool**：调度池，可包含其他可调度实体
- **TaskSetManager**：任务集管理器，管理具体任务的执行

## 接口属性定义和说明

### 1. 层次结构属性

#### `var parent: Pool`

**功能：** 父级调度池的引用

**设计意图：**
- **层次构建**：支持树状的调度层次结构
- **状态传播**：便于状态信息的向上传播
- **资源管理**：支持层次化的资源分配

**可变性设计：**
- 使用 `var` 支持动态的父子关系调整
- 支持运行时层次结构的动态构建
- 便于调度策略的灵活调整

### 2. 子队列管理属性

#### `def schedulableQueue: ConcurrentLinkedQueue[Schedulable]`

**功能：** 子可调度实体的队列

**数据结构选择：**
- **线程安全**：使用 ConcurrentLinkedQueue 保证并发安全
- **FIFO 顺序**：保持添加顺序，便于调度处理
- **动态管理**：支持实时的添加和移除操作

**设计特点：**
- 抽象方法，由具体实现提供具体队列
- 支持层次化的实体嵌套
- 便于调度算法的遍历处理

### 3. 调度配置属性

#### `def schedulingMode: SchedulingMode`

**功能：** 调度模式配置

**模式类型：**
- `SchedulingMode.FAIR` - 公平调度模式
- `SchedulingMode.FIFO` - 先进先出调度模式

**作用：**
- 决定调度算法的选择
- 影响任务执行的优先级策略
- 支持不同场景的调度需求

#### `def weight: Int`

**功能：** 权重配置，影响资源分配比例

**设计意图：**
- **比例控制**：权重高的实体获得更多资源
- **优先级实现**：通过权重实现隐式优先级
- **公平性保证**：在公平调度中实现公平分配

#### `def minShare: Int`

**功能：** 最小资源份额配置

**作用：**
- **资源保障**：确保实体获得最低限度的资源
- **饥饿避免**：防止低优先级实体完全无法获得资源
- **公平性基础**：在资源紧张时保证基本运行

### 4. 运行状态属性

#### `def runningTasks: Int`

**功能：** 当前运行的任务数量

**状态跟踪：**
- **实时监控**：反映实体的当前负载状态
- **调度决策**：影响后续任务的调度决策
- **资源管理**：为资源分配提供依据

#### `def priority: Int`

**功能：** 优先级配置

**当前状态：**
- 在现有实现中优先级概念使用较少
- 为未来优先级调度预留接口
- 支持扩展更复杂的调度策略

#### `def stageId: Int`

**功能：** 阶段标识符

**用途：**
- **调度决策**：在调度平局时提供 tie-breaking
- **阶段关联**：与特定阶段建立关联关系
- **状态管理**：支持阶段级别的状态跟踪

#### `def name: String`

**功能：** 实体的唯一名称标识

**设计特点：**
- **唯一性保证**：确保实体的唯一标识
- **查找支持**：便于在层次结构中定位实体
- **调试友好**：提供有意义的调试信息

### 5. 状态查询属性

#### `def isSchedulable: Boolean`

**功能：** 检查实体当前是否可调度

**设计意图：**
- **状态判断**：提供实体的调度状态信息
- **过滤支持**：支持调度时的实体过滤
- **条件调度**：实现基于条件的调度决策

## 接口方法分类和说明

### 1. 实体管理方法

#### `def addSchedulable(schedulable: Schedulable): Unit`

**功能：** 添加可调度实体到当前实体

**设计特点：**
- **层次构建**：支持调度层次结构的动态构建
- **类型安全**：参数类型为 Schedulable 接口
- **状态维护**：确保父子关系的正确建立

**实现要求：**
- 需要更新 schedulableQueue
- 需要设置实体的 parent 引用
- 需要维护相关的索引结构

#### `def removeSchedulable(schedulable: Schedulable): Unit`

**功能：** 从当前实体移除可调度实体

**设计特点：**
- **动态调整**：支持层次结构的动态调整
- **资源清理**：及时释放不再需要的资源
- **状态同步**：确保状态的一致性

**实现要求：**
- 从 schedulableQueue 中移除实体
- 清理相关的索引和引用
- 保持数据结构的完整性

#### `def getSchedulableByName(name: String): Schedulable`

**功能：** 根据名称查找可调度实体

**查找策略：**
- **直接查找**：在当前实体的子实体中查找
- **递归查找**：在子实体的层次结构中递归查找
- **空值返回**：未找到时返回 null

**设计特点：**
- **名称索引**：支持基于名称的快速查找
- **深度搜索**：支持层次结构的深度搜索
- **性能优化**：优先使用高效的查找算法

### 2. 执行器管理方法

#### `def executorLost(executorId: String, host: String, reason: ExecutorLossReason): Unit`

**功能：** 处理执行器丢失事件

**事件类型：**
- **执行器故障**：执行器意外终止
- **网络分区**：执行器与集群断开连接
- **资源回收**：执行器被系统回收

**设计特点：**
- **事件传播**：需要将事件传播给所有子实体
- **状态更新**：更新相关的执行器状态信息
- **故障恢复**：支持任务的重新调度和恢复

#### `def executorDecommission(executorId: String): Unit`

**功能：** 处理执行器停用事件

**事件场景：**
- **计划维护**：执行器的计划性下线
- **资源调整**：集群资源的动态调整
- **优雅关闭**：执行器的优雅停止过程

**设计特点：**
- **停用通知**：通知所有子实体执行器停用
- **资源迁移**：支持任务的迁移和重新调度
- **状态同步**：保持状态的一致性

### 3. 任务调度方法

#### `def checkSpeculatableTasks(minTimeToSpeculation: Long): Boolean`

**功能：** 检查是否需要启动推测执行

**推测执行条件：**
- **时间阈值**：任务执行时间超过指定阈值
- **进度落后**：任务执行进度明显落后
- **资源可用**：有可用的资源进行推测执行

**设计特点：**
- **条件判断**：基于时间阈值进行判断
- **结果聚合**：支持子实体的结果聚合
- **性能优化**：避免不必要的推测执行

#### `def getSortedTaskSetQueue: ArrayBuffer[TaskSetManager]`

**功能：** 获取排序后的任务集队列

**排序要求：**
- **算法应用**：根据调度模式应用相应的排序算法
- **层次收集**：从所有子实体收集任务集
- **状态过滤**：只返回可调度的任务集

**返回类型：**
- `ArrayBuffer[TaskSetManager]` - 排序后的任务集列表

**设计特点：**
- **排序抽象**：隐藏具体的排序算法细节
- **结果聚合**：支持层次化结果的聚合
- **接口统一**：提供统一的调度接口

## 配置参数说明

### 1. 调度模式配置

#### 调度算法选择
- `SchedulingMode.FAIR` - 公平调度模式
- `SchedulingMode.FIFO` - 先进先出调度模式

#### 配置影响
- 决定任务调度的优先级策略
- 影响资源分配的公平性
- 支持不同的业务需求

### 2. 资源分配配置

#### 权重配置（weight）
- **作用**：控制资源分配的比例
- **取值范围**：正整数，通常 1-10
- **默认值**：通常为 1

#### 最小份额配置（minShare）
- **作用**：保证最低资源分配
- **单位**：通常为任务槽位数量
- **默认值**：通常为 0

### 3. 状态跟踪配置

#### 优先级配置（priority）
- **当前状态**：在现有实现中使用较少
- **未来扩展**：为优先级调度预留
- **取值范围**：整数，值越小优先级越高
